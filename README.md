# Nutri Healthy

Сайт-витрина для health-коучинга ИП Каменская Ксения Александровна, ориентированный на российский рынок. Реализует публичную информацию об услугах, приём платежей, юридически значимую документацию по 152-ФЗ и требованиям Роскомнадзора, а также транзакционные email-коммуникации. Проект построен на Next.js App Router (страницы, API, legal, payment, materials, services) с серверным рендерингом и статической генерацией.

Кодовая база находится в активной разработке: финализирована юридическая база, внедрена платёжная инфраструктура с отказоустойчивостью, завершён переход на Unisender Go для email, консолидированы автотесты и шаблонизированы бизнес-реквизиты.

## Текущий этап разработки

На момент последнего обновления README проект сфокусирован на пяти ключевых направлениях:

1. **Юридическая база**
   Завершено 10 итераций доработки документов: публичный договор, политика конфиденциальности, согласие на обработку персональных данных, согласие на маркетинговые рассылки, условия возврата, условия доставки. Все документы приведены к единому строгому виду, имеют шаблонный механизм подстановки реквизитов ИП через `{{BUSINESS_*}}` и версионируются отдельными переменными окружения. В футере сайта используется единый юридический индекс со ссылками на актуальные версии.

2. **Платёжная инфраструктура**
   Поддержка двух провайдеров (ЮKassa, PayKeeper) с единой точкой переключения `PAYMENT_ENV_TYPE` (test/live). Реализовано 10 улучшений: валидация и санитизация входящих данных, exponential backoff с повторными попытками, сбор метрик для мониторинга успешности, graceful degradation с запасным сценарием (fallback), маскирование чувствительных полей в логах, rate limiting, картографирование ошибок провайдеров на унифицированные коды, юнит-тесты критических путей, версионирование webhook и timing-safe проверка подписи.

3. **Email-инфраструктура**
   Выполнена миграция с прежнего провайдера на Unisender Go. React Email используется для шаблонов писем. Предусмотрен запасной канал через Resend; выбор провайдера определяется наличием соответствующих ключей в окружении.

4. **Тестовая инфраструктура**
   Jest подключён, все тесты консолидированы в директорию `__tests__/`. Покрыты ключевые модули: платёжные сервисы, валидация, email-отправка, хелперы.

5. **Реквизиты ИП**
   Все бизнес-реквизиты (ФИО, ИНН, ОГРНИП, телефон, email, домен, адрес, регистрационный номер в реестре Роскомнадзора) вынесены в переменные окружения с префиксом `NEXT_PUBLIC_BUSINESS_` и подставляются в Markdown-документы, футер, email-сообщения и платёжные формы.

## Быстрый старт

```bash
git clone <repo-url> nutri-healthy-v1
cd nutri-healthy-v1
npm install
```

Создайте `.env.local` на основе примера:

```bash
cp .env.example .env.local
```

Обязательно заполните в `.env.local`:

- `MONGODB_URI` — строка подключения к MongoDB (локальной или Atlas)
- `NEXTAUTH_URL` и `NEXTAUTH_SECRET` — для NextAuth (если используется аутентификация)
- `UNISENDER_GO_API_KEY`, `UNISENDER_GO_API_URL` — ключ API и URL Unisender Go
- `EMAIL_FROM`, `EMAIL_TO` — адреса отправителя/получателя транзакционных писем
- `PAYMENT_ENV_TYPE` — выберите `test` или `live`
- Для выбранного окружения укажите ключи `YOOKASSA_TEST_*` / `YOOKASSA_LIVE_*` и `PAYKEEPER_TEST_*` / `PAYKEEPER_LIVE_*`
- Реквизиты ИП (`NEXT_PUBLIC_BUSINESS_*`) и версии юридических документов (`*_VERSION`)

Для локальной разработки запустите:

```bash
npm run dev
```

Приложение будет доступно по адресу [http://localhost:3000](http://localhost:3000). Убедитесь, что экземпляр MongoDB запущен и доступен.

## Переменные окружения

Все переменные окружения описаны в файле `.env.example` с пояснительными комментариями. Скопируйте его в `.env.local` и заполните актуальными значениями. Ниже приведено краткое назначение каждой группы.

### Приложение
**`NEXT_PUBLIC_URL`** — публичный URL развернутого приложения.
**`NEXTAUTH_*`** — параметры аутентификации NextAuth.js (секрет, URL, провайдеры).
Группа задаёт базовые настройки Next.js и механизма входа пользователей.

### MongoDB
**`MONGODB_URI`** — строка подключения к базе данных MongoDB.
Используется для хранения всех данных приложения: пользователей, заказов, подписок, юридических согласий.

### Email
**`UNISENDER_GO_*`** — ключ API и настройки сервиса Unisender Go для транзакционных и маркетинговых писем.
**`EMAIL_FROM`**, **`EMAIL_TO`** — адреса отправителя и получателя для служебных уведомлений (например, копии чеков).
Группа отвечает за отправку всех почтовых сообщений через Unisender Go.

### Платежи
**`PAYMENT_ENV_TYPE`** — единый переключатель режима работы всех платёжных провайдеров (`test` или `live`).
**`YOOKASSA_TEST_*`** / **`YOOKASSA_LIVE_*`** — реквизиты тестового и боевого магазинов ЮKassa (идентификатор, секретный ключ, webhook secret).
**`PAYKEEPER_TEST_*`** / **`PAYKEEPER_LIVE_*`** — реквизиты для PayKeeper в тестовой и боевой среде (идентификатор, ключ, секрет вебхука).
Значение `PAYMENT_ENV_TYPE` определяет, какой набор ключей используется **одновременно** для обоих провайдеров.

### Аналитика
**`NEXT_PUBLIC_YANDEX_METRICA_ID`** — идентификатор счётчика Яндекс.Метрики для сбора анонимной статистики посещений.

### Реквизиты ИП
**`NEXT_PUBLIC_BUSINESS_FULL_NAME`** — полное наименование ИП (ФИО).
**`INN`**, **`OGRNIP`**, **`PHONE`**, **`EMAIL`**, **`DOMAIN`**, **`ADDRESS`**, **`RKN_REG_NUMBER`** — регистрационные и контактные данные предпринимателя.
Эти переменные подставляются в юридические документы и отображаются в интерфейсе (футер, чеки, страница контактов). Префикс `NEXT_PUBLIC_*` сделан осознанно: реквизиты публичны и всё равно выводятся в HTML страниц.

### Версии юридических документов
Каждый документ имеет собственную переменную с номером версии:
`PRIVACY_POLICY_VERSION`, `CONTRACT_VERSION`, `PERSONAL_DATA_CONSENT_VERSION`, `HEALTH_DATA_CONSENT_VERSION`, `CROSS_BORDER_CONSENT_VERSION`, `MARKETING_CONSENT_VERSION`, `COOKIES_CONSENT_VERSION`, `RETURN_POLICY_VERSION`, `DELIVERY_TERMS_VERSION`, `OPERATOR_NOTIFICATION_VERSION`.
Номера версий позволяют отслеживать актуальность документов, фиксировать согласие пользователя с конкретной редакцией и при необходимости уведомлять об изменениях.

Для получения полного списка переменных и комментариев к ним обратитесь к файлу `.env.example` в корне проекта.

## Платёжная система

Управление платёжным окружением осуществляется одной переменной:

```
PAYMENT_ENV_TYPE=test | live
```

Она одновременно переключает режим **всех интегрированных провайдеров** — ЮKassa и PayKeeper. При значении `test` задействуются ключи из переменных `*_TEST_*`, при `live` — из `*_LIVE_*`. Это исключает ситуацию, когда один провайдер работает в тестовом режиме, а другой — в боевом.

Платёжный слой реализован с использованием абстракции провайдеров, что обеспечивает единообразное поведение:

- **retry** — автоматический повтор запроса при сбоях (exponential backoff с ограничением по числу попыток);
- **graceful degradation** — если временно недоступен один провайдер, система использует запасной сценарий (fallback) или корректно сообщает об ошибке пользователю;
- **rate limiting** — защита от превышения лимитов API платёжных систем и от злоупотреблений со стороны клиентов;
- **webhook-уведомления** — версионирование эндпоинтов и безопасная проверка подписи (timing-safe signature validation), что предотвращает атаки повторного воспроизведения и гарантирует целостность данных.

## Юридические документы

Исходные тексты юридических документов хранятся в директории `content/legal/` в формате Markdown. В них используются шаблонные заполнители `{{BUSINESS_FULL_NAME}}`, `{{BUSINESS_INN}}`, `{{BUSINESS_ADDRESS}}`, `{{BUSINESS_EMAIL}}` и другие, соответствующие реквизитам ИП из переменных окружения. При рендеринге страниц заполнители заменяются актуальными значениями из ENV.

Каждый документ имеет собственную переменную версии (`PRIVACY_POLICY_VERSION`, `CONTRACT_VERSION` и т.д., см. раздел «Переменные окружения»). Это позволяет:

- фиксировать, с какой именно редакцией пользователь согласился в момент регистрации или оформления заказа;
- отслеживать историю изменений и при необходимости запрашивать повторное согласие;
- обеспечивать соответствие требованиям Федерального закона №152-ФЗ «О персональных данных», включая формы согласий на обработку персональных данных, данных о здоровье, трансграничную передачу, получение маркетинговых рассылок и использование cookie-файлов. Учтены также требования Роскомнадзора к оператору персональных данных (регистрация в реестре, уведомления, публикация обязательных документов).

## Деплой

Проект рассчитан на деплой в среде Vercel, которая нативно поддерживает Next.js. Для развёртывания достаточно:

1. Подключить репозиторий к Vercel.
2. В настройках проекта на платформе задать все необходимые переменные окружения (из списка в `.env.example`) с разделением по окружениям (Development, Preview, Production).
3. Выполнить деплой — Vercel автоматически определит фреймворк и использует команды сборки из `package.json`.

Убедитесь, что все переменные, включая конфиденциальные секреты платёжных систем и Unisender Go, переданы корректно и не хранятся в открытом виде в коде репозитория.
